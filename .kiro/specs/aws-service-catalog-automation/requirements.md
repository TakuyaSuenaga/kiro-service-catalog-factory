# 要件定義書

## 概要

AWSサービスカタログへのプロダクト登録を自動化するGitHub Actionsワークフローシステム。CloudFormationテンプレートをバージョン管理し、OIDC認証を使用してAWSに安全に接続し、サービスカタログのポートフォリオとプロダクトを自動的に管理する。

## 要件

### 要件1

**ユーザーストーリー:** 開発者として、CloudFormationテンプレートをGitHubリポジトリにプッシュすることで、AWSサービスカタログに自動的にプロダクトを登録したい。これにより、手動でのサービスカタログ管理作業を削減できる。

#### 受け入れ基準

1. WHEN 開発者がポートフォリオフォルダ内にプロダクトフォルダを作成し、バージョンフォルダにCloudFormationテンプレートをコミットした場合 THEN GitHub Actionsワークフローが自動的にトリガーされ、AWSサービスカタログにプロダクトを登録する
2. WHEN 新しいポートフォリオまたはプロダクトがリポジトリに追加された場合 THEN GitHub Actionsワークフローが自動的にトリガーされる
3. WHEN プロダクトの新しいバージョンがコミットされた場合 THEN システムは既存のプロダクトに新しいバージョンを追加する
4. IF CloudFormationテンプレートに構文エラーがある場合 THEN ワークフローは失敗し、エラーメッセージを表示する

### 要件2

**ユーザーストーリー:** インフラ管理者として、フォルダ構造でプロダクトとバージョンを管理したい。これにより、プロダクトの履歴と構成を明確に把握できる。

#### 受け入れ基準

1. WHEN リポジトリ構造を確認する場合 THEN portfolios/[ポートフォリオ名]/[プロダクト名]/[バージョン]/template.yaml の階層構造でファイルが整理されている
2. WHEN 新しいバージョンを追加する場合 THEN 既存のバージョンフォルダを変更せずに新しいバージョンフォルダを作成できる
3. WHEN プロダクトメタデータを管理する場合 THEN 各プロダクトフォルダにproduct.yaml設定ファイルが存在する

### 要件3

**ユーザーストーリー:** セキュリティ管理者として、OIDC認証を使用してAWSに安全に接続したい。これにより、長期間有効なアクセスキーを使用せずに済む。

#### 受け入れ基準

1. WHEN GitHub ActionsがAWSに接続する場合 THEN OIDC認証を使用してアクセスキーを使わずに認証する
2. WHEN AWS接続設定を管理する場合 THEN リージョン、アカウントID、IAMロールはGitHubシークレット変数で管理される
3. IF OIDC認証が失敗した場合 THEN ワークフローは適切なエラーメッセージと共に失敗する

### 要件7

**ユーザーストーリー:** 開発者として、シンプルで保守しやすい実装でポートフォリオとプロダクトを管理したい。これにより、システムの複雑性を最小限に抑えることができる。

#### 受け入れ基準

1. WHEN ポートフォリオやプロダクトを登録する場合 THEN 可能な限りAWS CLIコマンドを使用して実装する
2. IF AWS CLIで実装が困難な場合 THEN AWS CDKを使用してPythonコードで実装する
3. WHEN 実装方法を選択する場合 THEN AWS CLI > AWS CDK (Python) の優先順位で技術選択を行う

### 要件4

**ユーザーストーリー:** 運用チームとして、ワークフローの実行状況とエラーを監視したい。これにより、問題を迅速に特定し解決できる。

#### 受け入れ基準

1. WHEN ワークフローが実行される場合 THEN 各ステップの進行状況がGitHub Actionsログに記録される
2. WHEN エラーが発生した場合 THEN 詳細なエラーメッセージとスタックトレースがログに出力される
3. WHEN サービスカタログの操作が完了した場合 THEN 成功メッセージと作成されたリソースの詳細がログに記録される

### 要件5

**ユーザーストーリー:** 開発チームとして、日本語のドキュメントでシステムの使用方法を理解したい。これにより、チーム全体が効率的にシステムを活用できる。

#### 受け入れ基準

1. WHEN リポジトリを初めて使用する場合 THEN 日本語のREADMEファイルでセットアップ手順が説明されている
2. WHEN フォルダ構造を理解する必要がある場合 THEN 各フォルダの目的と使用方法が日本語で文書化されている
3. WHEN トラブルシューティングが必要な場合 THEN よくある問題と解決方法が日本語で記載されている

### 要件6

**ユーザーストーリー:** 開発者として、実際に動作するサンプルプロダクトでシステムをテストしたい。これにより、システムが正常に機能することを確認できる。

#### 受け入れ基準

1. WHEN リポジトリを作成した場合 THEN Ubuntu 24.04 ARM SSMイメージを使用するEC2インスタンスをプロビジョンするサンプルプロダクトが含まれている
2. WHEN サンプルプロダクトをプッシュした場合 THEN GitHub Actionsワークフローが正常に動作し、AWSサービスカタログにプロダクトが登録される
3. WHEN サンプルプロダクトがサービスカタログに登録された場合 THEN AWSコンソールからプロダクトを起動してEC2インスタンスを作成できる
